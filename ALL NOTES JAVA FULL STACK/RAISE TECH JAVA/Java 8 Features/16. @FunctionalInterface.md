# @FunctionalInterface

@FunctionalInterface is an annotation introduced in Java 8 to indicate that an interface is intended to be a Functional Interface.

Example:

```java
@FunctionalInterface
interface Operation {
    int execute(int number);
}
```

**Important**

@FunctionalInterface does not make an interface functional. An interface is functional if it has exactly **one abstract method**.

The annotation only provides:

- Documentation of intent
- Compile-time validation
- Protection against accidentally adding another abstract method

Example:

```java
@FunctionalInterface
interface Operation {
    int execute(int number);
    int calculate(int number); // Compile-time error
}
```

**Allowed Methods**

A Functional Interface can contain:

- One abstract method
- Multiple default methods
- Multiple static methods
- Object method declarations

Example:

```java
@FunctionalInterface
interface Operation {

    int execute(int number);

    default void info() {
    }

    static void help() {
    }
}
```

Still functional because only execute() is abstract.

**Inherited Methods**

Inherited abstract methods are considered when determining whether an interface is functional.

```java
interface Parent {
    void execute();
}

@FunctionalInterface
interface Child extends Parent {
}
```

Child is functional because it effectively has one abstract method.

**Object Methods**

Methods corresponding to public methods of Object do not count toward the abstract method limit.

Examples:

- equals()
- hashCode()
- toString()

**Key Points**

- Introduced in Java 8.
- Optional annotation.
- Functional Interface = exactly one abstract method.
- Annotation validates the SAM rule at compile time.
- Default/static methods don't affect functional status.
- Object methods don't count toward the SAM rule.
- Recommended when intentionally designing a Functional Interface.

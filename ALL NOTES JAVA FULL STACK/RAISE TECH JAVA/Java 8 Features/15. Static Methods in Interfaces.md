# Static Methods in Interfaces

Java 8 introduced static methods in interfaces.

A static method belongs to the interface itself and not to implementing objects.

**Example:**

```java
interface Vehicle {

    static void printInfo() {
        System.out.println("Vehicle information");
    }
}
```

Call using the interface name:

```java
Vehicle.printInfo();
```

**Static Methods are not inherited**

```java
class Car implements Vehicle {
}
```

Invalid:

```java
Car.printInfo();
```

Also invalid:

```java
new Car().printInfo();
```

Interface static methods must be accessed using:

```java
InterfaceName.methodName();
```

**Purpose**

Static methods in interfaces are useful for:

- Utility methods
- Helper methods
- Factory methods
- Keeping related functionality inside the interface

Example from Java APIs:

```java
Comparator.comparing(Employee::getName);
```

**Static vs Default Methods**

| Default Method | Static Method |
| --- | --- |
| Belongs to object behavior | Belongs to interface |
| Inherited by implementing class | Not inherited |
| Can be overridden | Cannot be overridden |
| Called using object | Called using interface name |

**Functional Interface Compatibility**

Static methods do not count as abstract methods.

```java
@FunctionalInterface
interface Operation {

    int execute(int number);

    static void info() {
        System.out.println("Info");
    }
}
```

This remains a Functional Interface because it has only one abstract method.

**Same-name Static Method**

An implementing class can define a static method with the same name:

```java
Vehicle.printInfo();
Car.printInfo();
```

These are separate methods, not polymorphic overriding.

**Key Points**

- Introduced in Java 8.
- Belongs to the interface.
- Called using InterfaceName.methodName().
- Not inherited by implementing classes.
- Cannot be overridden.
- Useful for utility/helper/factory methods.
- Static methods don't affect Functional Interface SAM rules.
- Private interface methods came later in Java 9.

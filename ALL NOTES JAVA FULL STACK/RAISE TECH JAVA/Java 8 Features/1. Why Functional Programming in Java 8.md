# Why Functional Programming in Java 8?

Java 8 introduced functional programming features mainly to reduce the verbosity involved in representing small pieces of behavior.

Before Java 8, behavior was commonly represented using classes or anonymous classes.

Example:

```java
interface Operation {
    int execute(int number);
}

Operation square = new Operation() {
    @Override
    public int execute(int number) {
        return number * number;
    }
};
```

Java 8 allows the same behavior to be written using a lambda:

```java
Operation square = number -> number * number;
```

The compiler uses the target type (Operation) to determine which method the lambda implements.

If:

```java
interface Operation {
    int execute(int number);
}
```

Then:

```java
number -> number * number
```

matches:

- Input → int number
- Output → int

Equivalent conceptual form:

```java
number -> number * number
```

```java
(int number) -> {
    return number * number;
}
```

For a single-expression lambda:

- Parameter types can often be inferred.
- Curly braces can be omitted.
- return can be omitted.

Functional programming in Java enables behavior to be passed as an argument.

Example:

```java
static void process(int number, Operation operation) {
    System.out.println(operation.execute(number));
}
```

```java
process(5, number -> number * number);
process(5, number -> number * 2);
```

The same method can receive different behaviors.

## Key Points

- Java remains primarily object-oriented and multi-paradigm.
- Functional programming was added in Java 8.
- Main motivation: reduce anonymous class boilerplate.
- Behavior can be represented and passed using lambda expressions.
- Lambdas work with functional interfaces.
- A lambda's parameter and return type must match the functional interface's abstract method.
- Operation is an interface/type, not an object.
- square is a reference variable holding a lambda implementation compatible with Operation.
- Lambdas provide the foundation for APIs such as Streams.

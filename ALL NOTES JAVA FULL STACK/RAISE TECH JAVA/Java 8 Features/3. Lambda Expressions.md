# Lambda Expressions

A Lambda Expression is a concise way to provide an implementation for the single abstract method of a Functional Interface.

General syntax:

```java
(parameters) -> expression
```

or:

```java
(parameters) -> {
    // statements
}
```

A lambda gets its parameter types and return type from the target Functional Interface. This is called target typing.

Example:

```java
@FunctionalInterface
interface Operation {
    int execute(int number);
}

Operation square = number -> number * number;
```

The lambda is compatible with:

```java
int execute(int number) {
    return number * number;
}
```

**Lambda Forms**

No parameters:

```java
() -> System.out.println("Running");
```

One parameter:

```java
number -> number * number
```

Parentheses are optional for one parameter.

Multiple parameters:

```java
(a, b) -> a + b
```

Parentheses are mandatory.

**Expression Body**

```java
number -> number * number
```

For a single expression, the result is implicitly returned.

Equivalent:

```java
number -> {
    return number * number;
}
```

**Block Body**

```java
number -> {
    System.out.println(number);
    return number * number;
}
```

When using a block body, return must be explicitly written if the Functional Interface method returns a value.

**Parameter Type Inference**

Types can usually be omitted:

```java
(a, b) -> a + b
```

because they are inferred from the Functional Interface method.

Explicit types are also allowed:

```java
(int a, int b) -> a + b
```

Cannot mix typed and untyped parameters:

```java
(int a, b) -> a + b // Invalid
```

**Lambda vs Anonymous Class**

A lambda can conceptually replace an anonymous class implementation of a Functional Interface:

```java
Operation square = new Operation() {
    @Override
    public int execute(int number) {
        return number * number;
    }
};
```

However, internally a lambda is not simply compiled as an anonymous inner class. Java uses invokedynamic and runtime mechanisms for lambda implementation.

**Variable Capture**

A lambda can access local variables from its enclosing scope:

```java
int multiplier = 10;
Operation multiply = number -> number * multiplier;
```

Local variables captured by a lambda must be final or **effectively final**.

```java
int multiplier = 10; // Effectively final
Operation multiply = number -> number * multiplier;
```

A variable is effectively final when it is not declared with final, but its value is never reassigned.

```java
int multiplier = 10;
multiplier = 20; // Invalid if captured by a lambda
```

The variable cannot be reassigned after it is captured by the lambda. Attempting to reassign it causes a compile-time error (CTE).

```java
int multiplier = 10;
Operation multiply = number -> number * multiplier;
multiplier = 20; // Compile-time error
```

The lambda captures the value of multiplier, so Java requires multiplier to remain final or effectively final.

**Key Concept**

Functional Interface  
↓  
Single Abstract Method  
↓  
Defines parameters + return type  
↓  
Lambda provides implementation  

A lambda is not a standalone method. Its meaning comes from the target Functional Interface.
